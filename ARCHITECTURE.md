# Project Architecture: MADFAM Course Catalog

This document outlines the technical architecture of the MADFAM Course Catalog application.

## 1. Overview

The application is a web-based catalog for courses offered by MADFAM. It allows users to view available courses and potentially (based on API capabilities) add new ones. It uses a modern web stack focused on performance and developer experience.

## 2. Technology Stack

- **Framework:** [Astro](https://astro.build) (v5.x)
  - Used for building the user interface and handling routing.
  - Configured for **Server-Side Rendering (SSR)** using the `@astrojs/node` adapter, allowing dynamic data fetching and rendering on the server.
- **Backend Runtime:** [Node.js](https://nodejs.org/)
  - The environment where the Astro server runs.
- **Database:** [SQLite](https://sqlite.org)
  - A lightweight, file-based relational database. Chosen for simplicity and ease of setup for local development (`dev.db`).
- **ORM/Database Toolkit:** [Drizzle ORM](https://orm.drizzle.team)
  - Used for defining the database schema (`src/db/schema.ts`), managing database connections (`src/db/index.ts`), and performing database queries in a type-safe manner.
- **Language:** [TypeScript](https://www.typescriptlang.org/)
  - Used for type safety in database interactions, API handlers, and potentially components.
- **Package Manager:** [npm](https://npmjs.com/)

## 4. Data Flow

1.  **User Request:** A user accesses the main page (`/`).
2.  **Astro Routing:** Astro maps the `/` route to `src/pages/index.astro`.
3.  **Server-Side Fetching (`index.astro`):**
    - The `index.astro` page makes a `fetch` request to its own API endpoint `/api/courses`.
4.  **API Endpoint (`courses.astro`):**
    - The `GET` handler in `src/pages/api/courses.astro` is invoked.
    - It uses the Drizzle ORM instance (`db` from `src/db/index.ts`) to query the `courses` table in the SQLite database (`dev.db`).
    - It retrieves all course records.
    - It returns the course data as a JSON response.
5.  **Server-Side Rendering (`index.astro`):**
    - `index.astro` receives the JSON data from the API.
    - It passes the `courses` data as a prop to the `<CoursesSection>` component.
    - Astro renders the complete HTML page on the server, including the course list populated by the component.
6.  **Response:** The fully rendered HTML page is sent to the user's browser.

**(POST Request Flow):**

1.  A client (potentially a form or JS script) sends a POST request to `/api/courses` with new course data in the request body (JSON).
2.  The `POST` handler in `src/pages/api/courses.astro` is invoked.
3.  It parses the JSON data from the request.
4.  It uses Drizzle ORM (`db.insert()`) to add the new course data to the `courses` table.
5.  It returns a success response (e.g., status 201) with the newly created course data.

## 5. Key Components

- **`BaseLayout.astro`:** Provides the common HTML structure (head, body, potentially header/footer) for all pages.
- **`HeroSection.astro`, `AboutSection.astro`:** Static content components displayed on the main page.
- **`CoursesSection.astro`:** Responsible for receiving the list of courses and rendering them (likely iterating over the `courses` prop).
- **`db/index.ts`:** Initializes and exports the Drizzle database client instance.
- **`db/schema.ts`:** Defines the structure of the `courses` table.
- **`pages/api/courses.astro`:** The core backend logic for interacting with the course data.

## 6. Considerations

- **Scalability:** SQLite is suitable for small-to-medium traffic sites or local development. For larger scale, migrating to a database like PostgreSQL or MySQL would be necessary, requiring updates to the Drizzle configuration and potentially `index.ts`.
- **Authentication/Authorization:** Currently, there is no user authentication or authorization implemented. API endpoints are public.
- **Error Handling:** Basic error handling is present in the API endpoint, returning 500 for database errors and 400 for potentially invalid POST data. More robust error handling could be added.
- **State Management:** For more complex frontend interactions, a state management library (like Nano Stores, Zustand) might be introduced.
